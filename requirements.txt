UNIK SYSTEM PRO MAX — Profil & messagerie sécurisée
====================================================

Fichier client modifié :
  unik_system_pro_max_messagerie_profil.py

Dépendances existantes de l'application :
  pip install customtkinter pillow requests python-dotenv python-docx reportlab

IMPORTANT
---------
Le fichier fourni est le client Python Tkinter/CustomTkinter. Il appelle une API
distante Render, mais le code du serveur/API n'était pas inclus. Les écrans Profil
et Messagerie sont ajoutés côté client ; ils ne peuvent fonctionner complètement
qu'après ajout des routes ci-dessous au backend.

Routes attendues
----------------
1) POST /api/profile/update
   Authentification : Bearer JWT obligatoire.
   Corps JSON : {"display_name": "...", "email": "...", "avatar": "data:image/jpeg;base64,..."}
   Règles :
   - Modifier uniquement le profil de l'utilisateur du jeton, jamais un user_id fourni par le client.
   - Valider et normaliser display_name/email.
   - Limiter l'avatar à 500 Ko décodés, n'accepter que JPEG/PNG, vérifier le contenu réel.
   - Retourner {"user": {"id": "...", "username": "...", "display_name": "...", "email": "...", "avatar": "..."}}
   - Ne jamais retourner de mot de passe, hash, jeton ou secret.

2) POST /api/messages/users
   Authentification : Bearer JWT obligatoire.
   Retour : {"users": [{"id": "...", "username": "...", "display_name": "..."}]}
   Ne renvoyer que les champs publics nécessaires, sans e-mail si ce n'est pas nécessaire.

3) POST /api/messages/list
   Authentification : Bearer JWT obligatoire.
   Corps JSON : {"with_user_id": "..."}
   Retour : {"messages": [{"id": "...", "sender_id": "...", "recipient_id": "...",
                          "body": "...", "created_at": "..."}]}
   Sécurité impérative : ne renvoyer que les messages où l'utilisateur connecté est
   expéditeur ou destinataire et où l'autre membre correspond à with_user_id.

4) POST /api/messages/send
   Authentification : Bearer JWT obligatoire.
   Corps JSON : {"recipient_id": "...", "body": "..."}
   Retour : {"ok": true, "message": {...}}
   Sécurité impérative :
   - Déduire sender_id exclusivement du jeton JWT.
   - Vérifier que le destinataire existe et est actif.
   - Refuser les messages vides ou de plus de 4 000 caractères.
   - Ajouter created_at côté serveur, échapper/afficher le texte comme texte brut.
   - Limiter le débit par utilisateur et journaliser les échecs d'autorisation.
   - Ne jamais accepter un sender_id envoyé par le client.

Sécurité recommandée
--------------------
- HTTPS obligatoire ; ne pas exposer la clé API d'administration au client final.
- Toutes les routes doivent vérifier le JWT et l'état actif du compte.
- Autorisations contrôlées côté serveur ; cacher un bouton dans l'interface ne suffit pas.
- Mots de passe hachés avec Argon2id ou bcrypt côté serveur.
- Durée de vie courte des access tokens et mécanisme de révocation/renouvellement.
- Limitation du débit et taille maximale des requêtes.
- Ne pas journaliser les corps complets des messages ni les jetons.
- Sauvegarder la base et définir une politique de conservation des messages.

Ne pas considérer le système comme sécurisé en production tant que les routes backend
n'ont pas été implémentées et testées avec des comptes distincts (membre A, membre B,
administrateur), y compris les tests d'accès croisé non autorisé.
